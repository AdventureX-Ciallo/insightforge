## 项目基本信息

- 赛道：软件赛道
- 命题：商汤小浣熊“AI，不止完成一步” + 沙利文“PROOF OF INSIGHT”
- 作品名：InsightForge
- Slogan：AI，不止完成一步；让每条行业判断，经得起追问。
- 一句话定位：从一个行业问题，到一份能下钻、能质疑、能更新的研究成果。
- 产品形态：单用户、本地、离线优先的 72 小时 MVP

## 项目描述

InsightForge 是证据原生的行业研究 Agent。它不是回答问题的聊天框，而是把一个研究问题推进为计划、信源、PDF/表格解析、模型候选、确定性审查、人类判断和可编辑成果，并持续保留每条结论的依据、冲突、假设和来源变化影响。

产品研究依据是商汤小浣熊与沙利文两份官方命题。前者要求 multi-step Agent 与 multi-tool use 从需求走到成果；后者要求研究问题、证据、数据、判断和结论可连接、可追问、可更新，且人负责最终判断。当前没有真实用户调研，不声称市场需求或用户满意度已验证。

## 解决的问题

- 报告只保留结论，不保留形成过程。
- 来源观点、事实、计算、估算和预测混为一谈。
- AI 能快速生成看似合理但无依据的判断。
- 冲突被静默抹平，证据不足无法阻止确认。
- 来源更新后不知道哪些判断和成果需要重做。

## 目标用户

主要用户假设是需要把网页、PDF 和表格快速整理成研究判断与 PPTX 的行业分析师、咨询顾问、战略或投资研究人员；次要用户假设是需要审阅证据并决定最终文本的负责人。

## 三个核心场景

1. 接住任务：输入研究问题，五状态调用四类工具并交付三个成果。
2. 追问结论：模型只提出 3–5 条候选；用户下钻依据，查看冲突、不足和 Audit，再确认、驳回或编辑。
3. 跟踪变化：载入内置来源 v2 演示快照后，相关旧决定保留但失效、重新计算并生成新 PPTX/JSON 版本，无关结论保持不变。

## 黄金案例

本期只包含中国新能源乘用车与公共充电基础设施案例。原始公开来源、人工整理快照、派生 CSV 和合成两页 PDF 必须分开标识，详见 `docs/GOLDEN-SOURCE-MANIFEST.md`；当前不把演示材料称为权威原始报告。

## 技术架构

- Node.js `^20.19.0 || ^22.12.0 || >=23` / TypeScript 本地单体服务。
- Zod/JSON Schema 运行时合同。
- PDF.js 逐页解析。
- CSV 确定性公式计算。
- JSZip 生成可编辑 PowerPoint OOXML。
- React 工作台与 Playwright E2E。
- 本地 JSON 持久化，不使用数据库。
- 离线黄金路径外，强制验收一个显式预配置的 OpenAI-compatible 模型端点；无多模型路由或 fallback。

## 创新点

- 以任务链交付成果，而不是一次回答。
- 模型提出、程序校验、人类确认的权责分离。
- 支持项的 Conclusion→Claim→Evidence/Datum→Source→Locator 路径，以及不足项的 EvidenceGap 路径。
- 冲突与证据不足进入成果，而非在生成阶段被隐藏。
- 最小来源更新影响链使过期人工决定失效，同时保留原决定与旧成果历史。

创新不是功能数量，而是把完整任务链和证据责任做成同一个可运行产品。

## 安全与数据

- 服务强制 loopback-only。
- 固定工具和来源 URL allowlist。
- 文件限制为 PDF/CSV/XLSX/TXT、5 MiB，执行字节级校验和原子落盘。
- 来源文本安全转义；提示词注入只作为材料。
- 仓库不包含密钥、Cookie、`.env` 或真实用户数据。
