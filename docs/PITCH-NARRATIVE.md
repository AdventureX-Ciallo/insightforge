## 0:00–0:35 命题证据与问题

建议话术：

> 两份命题共同指出了今天 AI 的一个断点。商汤问：AI 能不能不止完成一步，而是从需求、规划、工具调用和校验走到成果？沙利文再追问：成果里的每条行业判断，能不能看见证据、处理冲突、保留假设，并在来源变化后知道什么需要重做？

画面只显示两条命题链，不先放技术架构。

禁止话术：`我们调研了很多用户`、`市场已经验证`。本期证据来自官方命题和项目所有者需求，不虚构用户数据。

## 0:30–0:50 一句话方案并立即启动

> InsightForge 是证据原生的行业研究 Agent：从一个行业问题，到一份能下钻、能质疑、能更新的研究成果。

同时显示三个场景标题：`接住任务 / 追问结论 / 跟踪变化`。

在 0:35 左右点击“运行黄金案例”，边解释一句话方案边让任务推进。路演构建目标是黄金任务 ≤50 秒；P0 的 3 分钟是稳定性上限，不是路演时钟预算。

## 0:50–1:35 场景一：接住整个任务

1. 点击唯一主按钮运行黄金问题。
2. 展示 `PLAN → COLLECT → SYNTHESIZE → AUDIT → DELIVER` 真实推进；离线模式说“加载并校验缓存计划/候选”，不说本次实时生成。
3. 简短指出搜索快照、PDF、表格计算和 PPTX 四类工具事件。
4. 落到交互报告、PPTX、JSON 三个成果。

一句证明：`前一步产物被下一步消费；任何一步失败，任务不会显示全部成功。`

## 1:35–2:55 场景二：追问一条结论

1. 点击一条结论，一次打开完整证据路径。
2. 展示 `37.1%` 与 `47.6%` 的不同口径，不选一个、不求平均。
3. 展示一次确定性计算，以及含 `15%` 明示情景假设的估算，直接区分事实、数据、计算、估算与判断。
4. 展示证据不足结论的 EvidenceGap，说明为什么没有伪造来源且不能确认。
5. 展示一次结构化 Audit 的 before/after；Audit 是本场景的系统子流程，不另讲第四场景。
6. 人工编辑或确认一条有证据的候选，保留原 AI 文本；冲突/估算确认时记录理由与范围，成果版本随之更新。

一句证明：`AI 只提出，程序审查，人对最终判断负责。`

## 2:55–3:50 场景三：来源变化让判断失效

1. 点击“检查来源更新”，同时指出这是“载入内置 v2 演示快照”，不是自动监控。
2. 展示受影响 Datum、Claim、Conclusion 和人工确认。
3. 展示无关结论保持不变。
4. 重新计算，并显示新的 PPTX/JSON 版本；旧决定与旧成果仍可审计。

一句证明：`不是重跑一份静态报告，而是只重审真正受影响的判断。`

## 3:50–4:25 可交付成果

打开五页 PPTX，现场编辑一个标题或数字；展示证据 JSON 的顶层对象。明确：

- 缓存搜索/模型输出用于断网稳定演示，标签持续可见。
- PPTX 灾备只在故障时使用，正常演示仍运行核心流程。
- 冲突、证据不足和待确认状态不会在导出时消失。

## 4:25–4:50 三根技术支柱

只讲：

1. 五状态编排与真实工具事件——证明任务确实推进。
2. Zod/JSON Schema 证据合同 + 输入驱动 Audit——证明判断可以校验。
3. 来源依赖与成果再生成——证明变化可以追踪到交付物。

不展开供应商路由、数据库、Agent 社会或与三场景无关的工程细节。

## 4:50–5:00 收束

> InsightForge 不试图证明 AI 无所不知。它证明一件更具体的事：一个 Agent 能把一次研究任务推进到可编辑成果，同时让证据可见、判断可质疑、变化可追踪。
