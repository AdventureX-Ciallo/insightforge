- 补建日期：2026-08-27

## 1. 背景

传统行业报告保留答案，却经常丢失答案形成的过程：数字属于事实、来源观点、计算还是预测不清楚；口径冲突被静默消解；证据不足的判断被写成结论；来源更新后无法知道哪些判断需要重做。

同时，真实研究工作不是一次问答，而是理解需求、规划、发现信源、读取文件、计算、综合、审查和交付的完整任务链。InsightForge 要以一个可运行原型同时证明多步骤 Agent 和可追问行业判断。

本 PRD 的一级调研证据是两份官方命题及项目所有者解释，逐条推导见 `docs/BRIEF-RESEARCH-EVIDENCE.md`：

- 商汤小浣熊：`需求 → 理解与规划 → 工具/系统调用 → 执行与校验 → 成果交付`。
- 沙利文：`研究问题 → 信源 → 证据 → 数据 → 事实/观点/估算 → 模型假设 → 判断 → 结论`，AI 加速、人负责最终判断。

两份命题足以支撑黑客松产品定义；当前没有真实用户使用证据，因此不声称市场采用或用户满意度已验证。

## 2. 产品目标

让研究执行者输入一个行业问题后，在一个工作台内完成三个核心场景：

1. `接住任务`：五状态调用四类工具并交付三个成果。
2. `追问结论`：3–5 条模型候选均能下钻依据，冲突、不足、Audit 和人工判断可见。
3. `跟踪变化`：来源更新使相关旧决定失效但保留历史、触发重算并刷新成果，无关结论不变。

## 3. 非目标

非目标以 `docs/DEVELOPMENT-SCOPE.md` 为准，包括通用聊天、第二行业案例、多 Agent、用户系统、向量库、任意爬虫、定时更新、多模型路由、无限修复、DOCX/XLSX 输出和生产级平台化。

## 4. 目标用户与核心任务

### 4.1 目标用户

- 主要用户假设：需要把网页、PDF 和表格在有限时间内整理成初步行业判断与 PPTX 的行业分析师、咨询顾问、战略或投资研究人员。
- 次要用户假设：需要审阅依据、处理争议并决定最终文本的项目负责人、业务负责人或高级研究员。

目标用户画像来自命题场景推导，尚无真实用户调研，不得写成已验证市场事实。

### 4.2 核心 Job to be Done

当我需要在有限时间内研究一个行业问题时，我希望 Agent 把资料获取、文件解析、计算、候选判断、审查和交付连成一条链，并明确告诉我哪些可以相信、哪些冲突、哪些缺证据，让我能够负责最终判断并在来源变化后快速复核。

## 5. 黄金案例与三场景

黄金问题：`中国新能源乘用车渗透率增长与公共充电基础设施之间，存在哪些约束迹象与证据边界？`

成功演示必须自然包含：

- 权威来源快照、带页码的合成演示 PDF、CSV v1/v2；资料身份见 `docs/GOLDEN-SOURCE-MANIFEST.md`；
- 40.9% 与 47.6% 的统计口径差异，以及 v1 预测/近似输入到 v2 终值的演示更新；
- 公共充电点增长计算和带 15% 假设的估算；
- “公共充电设施是渗透率增长的单一因果约束”这一判断的证据不足；
- 一次 Audit→Repair；
- 人工决定；
- 来源新版导致相关判断失效；
- 五页可编辑 PPTX 与证据 JSON。

三个场景的入口、失败路径和验收任务以 `docs/USER-FLOWS.md` 为准。

## 6. 产品原则

- 模型提出，程序校验，人负责最终判断。
- 缺证据时 fail-closed，不能默认通过。
- 来源说法不能自动升级为事实。
- 冲突保留双值，不求平均、不静默择一。
- 离线快照、缓存模型输出和实时调用必须显式区分。
- 一次自然任务链优先于功能按钮堆砌。
- 产品边界由状态和容器表达：AI 候选、人工确认、缓存模式、未入链文件不得混排或混称。

### 6.1 唯一研究对象与状态合同

PRD、用户流程、前端和验收共同引用 `docs/RESEARCH-OBJECT-MODEL.md`，不得各自定义另一套链路。

核心关系是：

`Conclusion → Claim → Evidence/Datum → Source → Locator`

估算/预测必须连接 `Assumption`；证据不足项走 `Conclusion → Claim → EvidenceGap`，记录已有部分材料与缺口，不为凑引用伪造 Source。机器状态拆为知识类型、责任来源、证据状态、人工审阅状态和新鲜度；`AI_JUDGMENT` 与 `HUMAN_CONFIRMED` 不是事实/估算的替代类型。

## 7. 功能需求

### FR-01 研究任务输入

- 输入 8–240 字符研究问题。
- 主流程固定填入黄金问题并提供一键运行，避免把单案例 MVP 伪装成通用研究产品。
- 非黄金领域问题仅放在折叠的“边界验证”入口。提交后主按钮改为“检查当前资料是否匹配”；若资料不匹配，必须输出问题相关的证据缺口，不能复用黄金结论。

### FR-02 PLAN

- 输出研究问题、范围和五个可执行步骤。
- 离线黄金模式加载并校验真实模型计划快照；显式在线模式才调用模型生成计划。两种模式都经过 Schema、工具白名单和问题匹配校验。
- 每个计划步骤必须映射到实际工具或确定性审查。

### FR-03 COLLECT

- 执行离线搜索索引、PDF 逐页读取、CSV/XLSX 输入读取与计算；黄金案例固定使用 CSV，XLSX 仅是 P0-03/P0-12 允许的输入类型，不生成 XLSX 成果。
- 产生 Source、Evidence、Datum 及精确 locator。
- 记录七字段工具事件。

### FR-04 SYNTHESIZE

- 产生 3–5 条候选结论。
- 默认离线黄金路径加载、消费并重新校验真实模型候选快照；在线增强路径调用一个显式模型端点生成候选。
- 每条候选引用一个或多个 Claim；Claim 再引用 Evidence/Datum/Assumption，或记录 EvidenceGap。不得让 Conclusion 用 `evidenceIds` 绕过 Claim/Datum。
- 未知 evidenceId、少于三条有效候选、模型/快照问题不匹配均阻断 SYNTHESIZE。
- 不得把开发者固定字符串标记为模型输出。

### FR-05 AUDIT

- 输入是当前结构化 Evidence、Datum、Claim、Conclusion。
- 检查 `MISSING_CITATION`、`UNSUPPORTED_CLAIM`、`SOURCE_CONFLICT`、`TYPE_MISMATCH`、`MISSING_ASSUMPTION`、`SCOPE_OVERREACH`。
- 规则必须根据输入内容而非对象固定 ID 判断。
- 补入真实支撑数据后不得继续无条件降级；伪造/悬空引用不能绕过。
- 最多一次自动修复，保留前后差异。
- 自动动作只允许结构归一、挂接已经存在的假设/来源、标记冲突、降级和阻断。程序不得凭空补假设或语义改写；新增假设/文本必须形成新的 AI 或人工候选版本，重新 Audit 并保持待确认。
- 确定性规则审查是 P0；一次独立的 LLM 审查阶段是可选增强，不能替代规则。若使用同一模型，只能称“独立审查阶段”，不得称“独立模型验证”。

### FR-06 DELIVER

- 同一运行对象驱动交互报告、五页 PPTX 和证据 JSON。
- 任何不足、冲突、预测和待确认状态不得在导出时消失。
- 首次交付生成 `ArtifactVersion v1`，文案为“成果已生成，含待审候选”。`DELIVERED` 只表示系统已交付真实状态，不表示全部结论已确认。
- 人工决定或来源更新后生成新的 ArtifactVersion；旧版本标记为已被取代并保留，不静默覆盖。

### FR-07 人工判断

- 候选默认 `PENDING_REVIEW`。
- 支持查看依据、确认、驳回、编辑。
- 记录时间、原模型版本和结果文本。
- 证据不足或 stale 结论不能确认。
- 编辑本身不自动等于确认；编辑后仍需重新审查并由用户显式确认。
- 确认冲突、估算或预测时必须记录 `decisionReason` 与 `scopeNote`。
- 每次确认、驳回或编辑后，交互报告、PPTX 和 JSON 生成同一新成果版本；旧决定与旧成果保留。

### FR-08 来源更新

- 内置来源 A v1/v2。
- 入口写“发现新版来源”，并持续说明这是“载入内置 v2 演示快照”，不冒充自动监控或全网发现。
- 应用新版后列出受影响对象，旧确认记录增加 `invalidatedAt/invalidationReason/sourceUpdateId`，重算并生成新成果版本；不得删除历史决定。
- 无关结论保持不变。

### FR-09 本地资料摄取

- 页面可选择 PDF/CSV/XLSX/TXT，最大 5 MiB。
- 服务器不信任扩展名/MIME，执行字节级校验和安全落盘。
- POST/GET/浏览器三方 SHA-256 必须一致才显示成功。
- 本期上传闭环是安全摄取能力；文件进入研究链需要显式解析/建模，不自动成为事实。
- 若文件尚未进入 COLLECT 证据链，入口只能称“验证并保存资料”，必须置于次要区域并显示 `已保存，尚未进入证据链`。

### FR-10 单一提供方在线信源发现

- 作为次要验证入口，只使用一个明确允许的搜索提供方和固定工具；查询必须来自当前研究问题。
- 返回标题、URL、摘要、查询时间和提供方状态，后续只有进入 COLLECT 并完成解析/建模的内容才能成为证据。
- 不抓取任意网站、不自动扩散查询、不配置多提供方路由；配置/网络失败即显示失败，不静默改用缓存。
- 至少保存一次真实成功和一次真实失败证据；离线搜索索引不能替代该验证。

### FR-11 权威来源实时核验

- 次要验证按钮只访问固定白名单 URL；该能力的冻结后验收是强制的，不得通过删除入口规避。
- 显示每个来源状态、字节数和摘要哈希。
- 失败逐项保留，不影响离线黄金任务，不冒充任意搜索。

## 8. 非功能需求

### NFR-01 可运行性

- Node.js 20+；`npm ci` 后无需改源码即可测试、构建、启动。
- 黄金任务断网可运行；单次不超过三分钟，目标 90 秒内。

### NFR-02 持久性

- 步骤进度和完整运行对象持久化；刷新和进程重启可恢复完整运行。
- 伪造或不完整状态必须拒绝恢复。

### NFR-03 安全

- loopback-only；固定工具和 URL allowlist；安全 DOM；无凭据；上传目录边界、权限、原子写和篡改检测。
- 来源中的提示词仅是材料，不改变计划、不读取环境变量、不调用额外工具。

### NFR-04 可解释与可复现

- 100% 结论有支持路径或机器可读证据缺口；支持路径中的引用 100% 有定位；100% 计算可重算。
- `sourceDiscoveryMode`、`authorityVerificationMode` 与 `synthesisMode` 在 UI、JSON 和 PPTX 中分别可见。

### NFR-05 兼容性

- Chromium E2E 必须通过。
- PPTX 在可用 Microsoft PowerPoint 环境实际打开和编辑；未具备的平台不能用替代工具冒充。

## 10. 发布与权限

本 PRD 当前只授权文档整理，不授权继续实现。只有项目所有者明确回复“文档冻结，可以开发”后，才可恢复本地实现、测试和打包。commit、push、PR、Git Tag、部署和线上配置始终需要项目所有者对具体操作单独明确授权。

## 11. 冻结后强制外部验收

- Windows 桌面 Microsoft PowerPoint 必须在对应环境完成打开、编辑、保存、重开；未完成前必须列为未验证风险。
- 真实上传入口必须用浏览器选择文件，完成 POST、持久化 GET 与浏览器 SHA-256 闭环；只测试 validator 不算通过。
- 单一提供方实时搜索、固定白名单来源核验与单端点在线 LLM 必须分别保存一次成功和一次配置/网络/Schema 失败证据；离线快照不能替代这些能力验证。
- 公开部署风险必须在项目所有者指定平台并授权后单独验证；未获授权前它是外部阻断，不允许部署，也不声称生产环境已验证。
- 在线模型凭据只由部署者在本机安全配置；不得从 ChatGPT 登录态提取或写入仓库。

## 12. 产品成功与失败

成功不是功能数量，而是五分钟内让观察者独立理解并看到：任务完整推进、结论可追溯且有边界、来源变化精确影响成果。量化阈值见 `docs/MVP-STRATEGY.md`。

出现任一项即失败：产品被理解为通用聊天；问题变化后复用黄金结论；固定剧本冒充模型或 Audit；上传成功冒充进入证据链；缓存快照冒充实时调用；任何 P0 未通过却声称 MVP 完成。
