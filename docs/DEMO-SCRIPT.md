# InsightForge 五分钟现场讲稿

> 适用版本：React 研究工作台。黄金案例离线运行，页面通过 SSE 接收五状态和工具事件；SSE 断线时自动降级轮询。不要把缓存快照说成实时搜索，也不要把待审候选说成最终结论。

## 演示前准备

- 按 README 启动同源服务，首页应显示“选择一个研究选题”。
- 不依赖网络或模型 API Key；网络能力只在“实时服务 · 信源 / 核验 / 模型”中按需触发。
- 现场正常运行完整任务，灾备成果只在浏览器完全不可用时使用。

## 0:00–0:35｜问题与双命题

操作：停留在“选择一个研究选题”。

讲稿：

“传统行业报告交付答案，却经常丢掉答案如何形成。InsightForge 接住一次完整研究任务，从问题推进到可编辑成果，同时保留证据、冲突、假设、人工判断和后续变化。

对商汤，它证明 AI 能接住整个任务；对沙利文，它让每条行业判断经得起追问。”

## 0:35–1:25｜商汤：五状态、四工具、模型提出

操作：点击“全功能研究案例”，进入任务页后点击“开始研究”，观察“任务进度”。

讲稿：

“一个任务真实经过 `PLAN → COLLECT → SYNTHESIZE → AUDIT → DELIVER`。模型提出计划和候选判断，确定性程序校验 Schema、工具白名单、证据引用和状态迁移；搜索快照、PDF、本地表格计算和 PPTX 生成不是四个孤立按钮，上一步产物会被下一步消费。

页面现在通过 SSE 实时接收步骤、工具和终态事件；连接异常时才降级轮询。缓存黄金案例会明确显示离线快照模式，不冒充本轮在线模型或实时搜索。”

指向“任务进度”的活动流，补一句：

“每个工具调用保留工具名、输入摘要、状态、输出 ID、耗时和错误；任一步失败，整条任务不会显示成功。”

## 1:25–2:20｜高光一：两次操作追到底稿

操作：任务结束后，点击底部“第 3 步 · 研究报告”，再在任一结论点击“查看依据”。

讲稿：

“这是第一个高光。两次操作就进入“证据路径”：从 Conclusion 向下经过 Claim、Evidence 或 Datum，直到 Source 和 Locator。网页保留 URL，PDF 保留页码，CSV 保留列名、行号、输入和公式。

来源对同一指标给出不同数值时，两边平等保留；差异解释只是候选解释，系统既不静默选一个，也不求平均当答案。”

关闭抽屉，指向结论卡和“审查修正”：

“AI 内容默认待审；类型、证据状态、审阅状态和新鲜度都以机器可读字段保存。确定性审查展示 before/after，自动修复最多一次，严重缺口仍在就进入 NEEDS_REVIEW。”

## 2:20–3:20｜人负责判断；变化精确传播

操作：对一条可审结论选择“确认”“驳回”或“编辑”；随后点击“第 4 步 · 变化”，再点击“检查来源更新”。

讲稿：

“人负责最终判断。确认、驳回和编辑都会留下时间、理由与原始模型文本；证据不足和过期结论不能自动确认。

这里把来源 A 从 v1 切到 v2：只让依赖它的对象变为 STALE，旧决定保留并失效，无关结论保持不变；系统重算受影响数据，并生成新的成果版本。‘来源更新，精确影响成果’展示的是可审计版本链，不是覆盖旧答案。”

## 3:20–4:00｜真实交付

操作：点击“第 5 步 · 交付”，展示“成果交付”。

讲稿：

“交付不止是聊天文本。当前页面是交互报告，同时生成可编辑五页 PPTX、证据 JSON、Markdown 和 PDF。四个下载成果共享同一研究快照；冲突、假设、待审和证据不足不会在导出时消失。”

## 4:00–4:40｜高光二：非黄金问题诚实拒答

操作：重置工作台，回到“选择一个研究选题”，点击任一“边界验证 · 运行返回证据缺口”卡片，然后点击“开始研究”。

讲稿：

“第二个高光不是再背一套答案，而是换成超出内置资料范围的问题。后端重新处理当前问题，但不会把新能源车材料硬套过去；系统进入 NEEDS_REVIEW，列出 EvidenceGap 和缺少的一手信源、指标口径、时间序列与交叉验证材料。

这证明它知道什么时候不能下结论，而不是用流畅文字掩盖证据空白。”

## 4:40–5:00｜收束

讲稿：

“InsightForge 证明的是：一个 Agent 能接住完整研究任务，用多步骤、多工具和模型提出候选，再用确定性规则、人类裁决和版本链，让判断可追问、可质疑、可更新，最后交付可继续编辑和复用的成果。”

## 评委追问预案

### 1. “能不能换一个问题？”

“可以。现场点击边界验证选题；匹配时产生可追溯候选，不匹配时进入 NEEDS_REVIEW 并列出 EvidenceGap。当前只内置一个行业黄金资料集，没有用第二套预写答案伪装通用性。”

### 2. “现场断网怎么办？”

“黄金案例完整离线运行。搜索快照、PDF、CSV 计算、认证模型缓存和 PPTX 都在本地；可选的‘运行白名单核验’失败会如实显示，不影响离线主链。”

### 3. “没有模型 API Key 还算 AI 吗？”

“黄金案例采用真实模型产出的认证缓存，并校验问题、提示词摘要、Schema、证据 ID、假设 ID 和关键数值。在线端点未配置时会 fail-closed；页面不接收或回显 API Key。‘实时候选生成 · 多模型端点’只显示部署者预配置状态。”

### 4. “来源里有提示词注入怎么办？”

“来源指令只是不可信材料，不能改计划、工具白名单或确认状态，也不能读取环境变量。‘资料库 · 验证并保存文件’先限制类型、大小与路径，再做浏览器、上传回执和落盘三方 SHA-256 核验。”

## 演示禁语

- 不说实时搜索成功，除非当场真实调用并看到成功。
- 不说 AI 已确认结论；准确说法是“AI 提出候选，人显式确认”。
- 不把 INSUFFICIENT_EVIDENCE、CONFLICT 或 NEEDS_REVIEW 说成系统故障。
- 不声称已部署、已在 Windows PowerPoint 验证或已做自动全网监控。
