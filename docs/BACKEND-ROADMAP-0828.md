## 纪要对既有约束的更新（以纪要为准）

- 交付格式扩展为 **PDF、MD、PPT、JSON**（DOCX/XLSX 输出仍然禁止）。
- 来源更新/搜索支持**用户选择搜索引擎**（百度/Google/Bing）——用户手选单引擎不等于多提供方自动路由，允许。
- 首页 3 个预设案例入口——需要 3 个预设研究问题（1 个黄金 + 2 个非黄金走边界/缺口路径），以 API 提供；仍不做第二个行业的完整黄金 fixtures（非黄金问题按失配诚实缺口处理）。
- 信源规模 ≤10、深度优先。

## P1 — 核心演示链（今天上午必须完成）

1. **成果版本链 V1→V5**：每次人工决定（确认/驳回/编辑）与来源 v1→v2 更新都产生新成果版本；每版本记录：交付内容、对应来源、调整依据（humanDecision/sourceUpdate 引用）。API 暴露版本列表与单版本详情，供前端第四页按 V1→V5 展示。
   验收：一次黄金 run + 2 次人工决定 + 1 次来源更新后，版本链 ≥4 且每版本可回溯依据；测试覆盖。
2. **多格式导出 MD + PDF**：新增 Markdown 报告导出（结论+证据+冲突+假设+来源定位，复用证据包数据）；PDF 用已内置的 Playwright Chromium `page.pdf()` 从导出页渲染（中文已验证可用）。JSON/PPTX 已有。
   验收：DELIVER 产出四类真实文件（.md/.pdf/.pptx/.json）进入 artifacts 与版本链；干净目录 E2E 断言四文件存在且 PDF 含中文文本。
3. **边界验证 API**：研究完成后输出 3 个"非黄金领域关联小问题"及其证据缺口（复用失配综合的缺口逻辑），端点如 `GET /api/runs/:id/boundary-questions`。
   验收：黄金 run 返回 3 个问题，每个带缺口说明；测试覆盖。

## P2 — 在线能力三件套（今天下午）

4. **模型端点配置 API**：`GET/POST /api/settings/llm`——运行时配置 baseUrl/model/key（key 只写不回显，返回掩码）；落盘到 `.insightforge/settings.json`（gitignore），引擎读取顺序：API 设置 > 环境变量。仍单端点、fail-hard。
   验收：配置后下一次 run 记录 llm-planner/llm-synthesizer 事件；未配置时离线行为与基线完全一致；GET 永不返回明文 key。
5. **搜索引擎选择**：来源更新模块支持用户选择 Bing/Google/Baidu；实现为所选引擎的查询 URL 模板 + 结果解析为候选信源（仅候选，解析/建模前不是证据）。**安全硬约束：服务端发请求仅 http/https；请求前校验 host；拒绝 localhost、环回、私有与保留地址；目标域必须在引擎白名单内**。
   验收：选择引擎后返回候选信源列表带 URL/标题/引擎标识；对内网/环回/非白名单目标的尝试被拒绝并有测试。
6. **信源置信度权重**：按域名分类的静态权重表（政府/协会/官网高，devpost/权威赛事高，知乎/小红书低），多维度（权威度/新鲜度/完整度）落到 source 对象与证据链展示。
   验收：黄金案例全部信源带权重与维度；低权重信源支撑的结论在 UI 数据里可见权重折扣说明；测试覆盖权重表应用。
