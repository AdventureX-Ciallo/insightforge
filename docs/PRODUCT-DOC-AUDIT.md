## 2. 已采纳的可靠问题

| Pro 发现 | 独立判断 | 文档动作 |
|---|---|---|
| Source/Evidence/Datum/Claim/Conclusion 在各文档和 UI 路径不一致 | 可靠；沙利文明确要求“证据→数据→判断→结论” | 新增 `RESEARCH-OBJECT-MODEL.md`；PRD/流程/前端改为唯一对象链 |
| FACT/AI_JUDGMENT/HUMAN_CONFIRMED 混在同一类型轴 | 可靠；知识类型、责任来源、人工状态不同 | 定义知识、来源、证据、审阅、新鲜度五个正交轴，同时保留 P0 所需机器标签 |
| “100% 结论有来源”与证据不足项冲突 | 可靠；为不足项伪造来源会违反 fail-closed | 改为 100% 支持路径或 EvidenceGap；支持引用仍 100% 可定位 |
| DELIVER、人工决定、来源更新与成果刷新没有版本生命周期 | 可靠；否则旧确认与旧 PPTX 会被覆盖 | 定义 ArtifactVersion；旧决定/旧成果保留并记录失效原因 |

独立结论：`40.9%` 与 `47.6%` 可用于口径差异高光，但不能叫“完全相同指标的两个真值”；当前两页 PDF 是项目合成摘要，不是官方原始 PDF；A-v1 映射 O0 预测，A-v2 映射 O1 正式结果；历史 `31.436` 列已决定从重建资产删除。这些均已写入资料清单，不再隐藏。

- 业务实现必须按唯一对象模型、EvidenceGap、CandidateRevision、ArtifactVersion 和三模式字段重新审计。

这些事项是恢复开发后的实现/验收，不再反向作为文档冻结前置条件。
