## 1. 产品结果

在五分钟内证明：一个行业研究 Agent 能接住一次完整研究任务，真实调用搜索快照、PDF、本地表格计算和 PPTX 生成工具，并在交付成果时保留信源、证据、计算、冲突、假设、模型候选、人工判断和来源变化影响。

选择同一软件赛道作品同时响应两个命题：

- 商汤小浣熊：`AI，不止完成一步`——重点证明多步骤推进、多工具协同和可编辑成果交付。
- 沙利文：`PROOF OF INSIGHT`——重点证明结论可追溯、冲突可见、证据不足会阻断、判断可人工确认、变化可追踪。

产品只讲三个核心场景：接住完整任务、追问一条结论、来源变化让判断失效。十二条 P0 是这三个场景的执行与质量约束，不扩展为十二套孤立功能。

## 2. 本期唯一黄金案例

研究问题：`中国新能源乘用车渗透率增长与公共充电基础设施之间，存在哪些约束迹象与证据边界？`

本期只交付这一个行业案例。更换研究问题用于 fail-closed 泛化测试，不构成第二个行业案例，也不得用新能源预写结论回答不相关问题。

## 3. 必须开发的范围

### 3.1 五状态工作流

`PLAN → COLLECT → SYNTHESIZE → AUDIT → DELIVER`

- 每一步持久化 `pending/running/success/failed`。
- 前一步 `outputId` 必须由下一步 `consumedOutputIds` 消费。
- 任一步失败，后续步骤不能显示全部成功。
- 自动修复最多一次；严重问题未消除则 `NEEDS_REVIEW`。

### 3.2 模型提出、程序校验

- PLAN：离线黄金模式加载并校验来源可审计的模型计划快照；在线模式才调用一个显式配置的模型端点生成计划。
- SYNTHESIZE：离线模式加载并校验真实模型候选快照，在线模式生成候选；不得把开发者手写固定结论冒充 AI 输出。
- 程序负责校验 evidenceId、结论数量、状态、引用、假设和范围；校验失败必须 fail-closed。
- 离线模型快照必须明确标记为缓存模型输出，不能冒充本次实时调用。
- 人负责最终确认；模型输出默认 `PENDING_REVIEW`。

### 3.3 四类真实工具

- 明确标记的离线搜索索引，或单一允许的实时信源发现工具；固定白名单来源核验是独立辅助验证，不冒充搜索。
- PDF/本地文件正文读取并保留页码。
- CSV/XLSX 读取和至少一次确定性公式计算。
- 生成可继续编辑的五页 PPTX。

### 3.4 证据原生研究对象

唯一对象合同见 `docs/RESEARCH-OBJECT-MODEL.md`。必须持久化 `SourceVersion/Source/Locator/Evidence/Datum/Assumption/Claim/EvidenceGap/Conclusion/CandidateRevision/AuditFinding/HumanDecision/ArtifactVersion` 的连接。

支持充分的结论走 `Conclusion → Claim → Evidence/Datum → Source → Locator`；证据不足结论走 `Conclusion → Claim → EvidenceGap`，不能为凑引用伪造来源。

状态拆为知识类型、责任来源、证据状态、人工审阅状态和新鲜度。`FACT/SOURCE_OPINION/CALCULATION/ESTIMATE/FORECAST` 与 `AI_JUDGMENT/HUMAN_CONFIRMED` 均机器可读，但不混在一个会丢失信息的字段中。

### 3.5 审查、人类决定与来源更新

- Audit 读取本轮结构化输入，检查六类问题；不得按固定对象 ID 回放结果。
- 同一规则在补充真实数据、删除引用或改变数值后必须产生不同发现。
- 自动动作只允许挂接既有材料、标冲突、降级和阻断；新增假设或语义改写必须形成新 AI/人工候选并重新审查。
- 人可以查看依据、确认、驳回、编辑；编辑保留原模型文本且不自动确认。冲突/估算/预测的确认记录理由与范围。
- v1→v2 更新只使依赖对象失效；旧人工决定保留失效原因，重算后生成新的 PPTX/JSON ArtifactVersion，旧成果不删除。

### 3.6 三个成果

- 当前网页即交互式研究报告。
- 固定模板、五页、文本可编辑的 PPTX。
- 包含问题、信源版本、证据、数据、假设、Claim、结论、审查、人工决定和成果版本索引的 JSON。

### 3.7 本地资料安全摄取

- UI 提供 PDF/CSV/XLSX/TXT 文件选择，单文件不超过 5 MiB。
- 浏览器→HTTP→字节校验→安全持久化→GET 复核→浏览器 SHA-256 比对形成闭环。
- 入口统一称“验证并保存资料”；成功状态统一为“已保存，尚未进入证据链”。本期黄金任务读取内置 PDF/CSV；任意上传文件只有经过显式解析、建模和审查后才可进入研究对象。
- 未入链上传不得置于主任务输入区或使用“加入研究”的文案。

### 3.8 分离的在线与外部验收能力

- 次要“在线能力验证”区提供单一搜索提供方的实时信源发现；成功结果先标为候选来源，只有进入 COLLECT 并解析/建模后才可成为证据。
- 固定白名单权威来源核验是独立动作；它只核验指定页面，不冒充实时搜索。
- PLAN/SYNTHESIZE 提供单一预配置模型端点的在线模式；缺配置、网络失败、Schema 失败或引用非法都显式失败，不静默回退缓存。
- 页面、运行 JSON 与 PPTX 分别保存 `sourceDiscoveryMode`、`authorityVerificationMode` 与 `synthesisMode`，不能合成一个模糊“在线”标签。
- 上传、实时信源发现、白名单核验、在线模型和 Windows PowerPoint 都是冻结后的强制验收项，但仍作为次要验证能力，不扩展为新的核心产品场景。

## 4. 明确不开发

- 通用聊天机器人、第二行业案例、多 Agent 群体、自主创建 Agent。
- 用户系统、多人协作、权限系统、云项目空间。
- 向量数据库、通用知识图谱编辑器、自动全网监控、定时更新、任意爬虫。
- 多模型路由、模型自动降级、无限修复循环。
- DOCX/XLSX 输出、多 PPT 主题、移动端专项适配。
- 完整密码学 provenance、大规模性能工程、生产级多租户安全。

## 5. 从 EvoForge 继承与废弃

继承：简化确定性状态机、程序校验、Zod/JSON Schema、fail-closed、运行事件日志、一次修复闭环。

不继承：12 状态控制器、多轮无限自迭代、模型供应商锁定、完整密码学证明、多 Agent 社会、浏览器 15 Gate、完整知识图谱和无人值守长期运行。

## 7. 范围变更规则

任何新增功能必须回答：

1. 它对应哪个 P0 或哪条命题证据？
2. 是否破坏禁止清单或五分钟演示？
3. 是否新增凭据、外部写入或部署权限？
4. 是否需要更新 PRD、前端需求和验收测试？

无法映射到 P0 的功能默认不进入 72 小时 MVP。

## 8. Definition of Done

### 文档阶段完成

- `docs/DOCUMENT-INDEX.md` 的冻结检查项无未解释冲突。
- 命题、PRD、范围、三场景、用户流程、前端、风险、路线图和验收矩阵一致。
- 所有者明确回复“文档冻结，可以开发”。

### 未来 MVP 完成

只有冻结后的 PRD 中十二条 P0 全部通过、干净目录回放通过、证据文件持久化且没有未披露的模拟/替代验证时，才能称本地 MVP 完成。真实上传、Windows PowerPoint、实时搜索、白名单核验和在线 LLM 必须按 `PRD.md §11` 分别保存真实成功/失败证据，不能用本地构建或离线快照替代。项目所有者还要求最终核验公开部署风险；该项在获得具体平台与操作授权前保持外部阻断，任何本地结果都不能冒充生产部署验证。
