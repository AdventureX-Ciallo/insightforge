# InsightForge 前端需求书

- 版本：`DRAFT 1.3`
- 状态：`IMPLEMENTED — ABloom React 工作台已完成主路径联调；以 E2E 与后端合同持续验收`
- 适用入口：本地 Web 工作台 `/`
- 目标桌面尺寸：评委笔记本 Chromium；不做移动端专项适配

## 1. 前端目标

前端不是聊天框，也不是四个孤立工具按钮。它必须让评委在五分钟内只沿一条叙事看见三个场景：接住完整任务、追问一条结论、来源变化推动成果更新。

## 2. 信息架构

单页只有三个一级章节：

1. `任务`：研究问题、唯一主按钮、五状态进度、计划与工具调用摘要。
2. `研究报告`：候选结论、证据下钻、冲突/不足、Audit 与人工决定。
3. `变化与交付`：来源 v1/v2 影响、重新计算、PPTX/JSON 下载。

跨章节固定元素：

- 顶栏：产品名、黄金案例版本，以及三组独立标签：`来源发现`、`来源核验`、`候选生成`；模式也进入 JSON/PPTX。
- 证据路径抽屉。
- 人工编辑对话框。
- 次要“资料摄取”区域；未入链上传不得出现在主 Hero。

低保真层级：

```text
┌ 产品名 ── 当前模式 ── 黄金案例版本 ┐
│ 研究问题                    [运行任务] │
├ 任务：五状态 → 计划/工具摘要          ┤
├ 研究报告：结论 → 证据/Audit/人工决定   ┤
└ 变化与交付：v1→v2 → PPTX / JSON       ┘
              [证据抽屉] [编辑弹窗]
```

不得增加登录、侧边聊天、项目列表、多人头像或与本期无关的设置页。

## 3. 核心页面状态

### 3.1 初始状态

- 默认问题为黄金问题。
- `运行黄金案例` 是唯一主按钮。
- 非黄金问题只在折叠的“边界验证”内编辑，按钮写“检查当前资料是否匹配”。
- 离线黄金路径同时显示 `来源发现：缓存搜索快照`、`来源核验：未运行`、`候选生成：缓存模型输出`。
- “资料摄取”和固定白名单核验放在折叠的次要区域，不能与“运行任务”争夺主操作。
- 折叠的“在线能力验证”区分别提供来源发现、白名单核验和候选生成控制；不能用一个总开关混合三种状态。

### 3.2 运行中

- 创建任务后立即滚动到工作区。
- 五步骤逐步显示 `pending/running/success/failed`。
- 至少真实观察到一个 `running`，不能一次性播放预写动画。
- 轮询 API；刷新后从持久状态恢复。
- 任一步失败时显示安全错误，后续步骤不能伪装成功。

### 3.3 已交付/待复核

- 标题显示原研究问题。
- 显示 `DELIVERED/NEEDS_REVIEW/FAILED`。
- 分别显示 `sourceDiscoveryMode`、`authorityVerificationMode` 与 `synthesisMode`。候选生成可为`缓存模型输出`、`实时单端点`或`确定性失配阻断`；不得把规则文本叫作实时 AI 输出。

### 3.4 空结果与失败状态

- 无匹配资料不是空白页，而是问题相关的证据缺口清单。
- 任一步失败时，错误出现在对应状态和页面顶部，保留已完成步骤产物。
- 不能用绿色终态、自动跳转或成果下载掩盖 `FAILED/NEEDS_REVIEW`。

## 4. 一级章节一：任务

- 展示研究范围、五步计划和实际工具映射。
- 展示离线/在线模式和候选来源。
- 展示信源数、证据数、计算数、候选结论数、修复次数，但默认不让计数取代任务叙事。
- 默认用“资料、数据项、判断、依据、版本”显示任务摘要；七字段工具事件放在可展开的“核验详情”中，展开后显示 `toolName/inputSummary/startedAt/status/outputId/duration/error`。
- 计划中每个工具必须能在事件或 Audit 阶段找到对应执行证据。

## 5. 一级章节二：研究报告

“候选结论”是默认视图；证据底稿与 Audit 作为结论上下文展开，不设置三个互相割裂的一级页签。

### 5.1 候选结论

每张卡必须显示：

- 当前结论文本；
- 知识类型：`FACT/SOURCE_OPINION/CALCULATION/ESTIMATE/FORECAST`（按适用对象）；
- 责任来源：`SOURCE_EXTRACTED/DETERMINISTIC/AI_JUDGMENT/HUMAN_EDITED`；
- 证据状态：`SUPPORTED/CONFLICT/INSUFFICIENT_EVIDENCE`；
- 人工状态：`PENDING_REVIEW/HUMAN_CONFIRMED/HUMAN_REJECTED/NEEDS_REVIEW`；
- 新鲜度：`CURRENT/STALE`；
- 候选来源（缓存模型或实时模型）；
- 来源编号；
- `查看依据/确认/驳回/编辑`，四项对每条候选均可发现。

规则：

- 证据不足和 stale 项禁用确认，并解释原因；仍允许编辑，但编辑后必须重新审查，不能自动成为 `HUMAN_CONFIRMED`。
- 编辑弹窗显示原模型文本将被保留。
- 编辑保存与确认是两个动作；只有显式确认后才显示时间和确认文本。
- 冲突、估算或预测的确认弹窗要求填写简短理由和适用范围。
- 冲突不得使用单一“正确数字”视觉覆盖另一值。

### 5.2 证据下钻

点击任意结论一次打开抽屉。有支撑的路径按顺序展示：

`Conclusion → Claim → Evidence/Datum → Source → Locator`

估算/预测在 Claim 下显示 Assumption。证据不足项改为 `Conclusion → Claim → EvidenceGap`，展示已有部分材料、缺少什么和为何不能确认；没有真实来源时不渲染虚构 Source。

Locator 至少展示 URL/标题/摘录、PDF 文件名与页码、CSV 列与行，或计算公式/输入/单位/期间。不得要求跳转超过两次才能看到原始依据。

所有来源摘录使用 `textContent`；不渲染来源 HTML，不执行其中指令。

### 5.3 审查修正

- 六类审查按卡片展示 category、severity、target、status、message、action。
- `before` 与 `after` 并排或前后明确可比。
- 显示修复次数，最大为 1。
- 区分已修复和需人工处理。
- 不允许只显示“自检通过”文本。
- 自动动作只显示挂接既有材料、标冲突、降级或阻断；新增假设/语义改写必须显示为新的 AI/人工候选版本并重新待审。

## 6. 一级章节三：变化与交付

### 6.1 来源更新

- 初始显示 v1 与“发现新版来源”按钮，副说明固定为“载入内置 v2 演示快照”。
- 点击后显示 v1→v2 差异和受影响对象列表。
- 相关结论显示 `STALE/NEEDS_REVIEW`；原决定保留并显示失效时间、原因和 updateId。
- 无关结论保留原文，并在 E2E 中进行字节级/文本等价断言。
- 更新后 PPTX/JSON 新版本号和哈希可见，旧版本仍可审计。

### 6.2 成果交付

- 交互报告卡标记为当前页面。
- PPTX 卡展示大小、SHA-256、下载按钮和“可编辑五页模板”。
- JSON 卡展示大小、SHA-256、下载按钮和结构说明。
- 下载响应必须是实际文件；PPTX 具有 ZIP 签名和正确文件名。
- 初次 DELIVER 显示“成果已生成，含待审候选”；人工决定、编辑或来源更新后，三项成果同步生成新 ArtifactVersion，不静默覆盖。

## 7. 次要能力：资料摄取

- `input[type=file]` accept PDF/CSV/XLSX/TXT。
- 显示 5 MiB 限制和“上传不等于成为证据”的说明。
- 上传成功后保存服务端返回的 upload ID；启动任务时将选中的 ID 通过 `POST /api/runs` 的 `uploadIds` 数组传入。只有运行对象返回该 ID 且出现 `local-file-reader` 事件后，UI 才能写“已进入本轮 COLLECT”；否则只显示“已验证并保存”。
- 成功文案只有在浏览器本地 SHA、POST 回执和 GET 复核三者一致后显示。
- 成功只用纯文本展示原文件名、净化文件名、大小和 SHA。
- 拒绝伪装格式、超限、路径穿越、NUL/非法 UTF-8、异常 XLSX；错误不含服务器路径或环境信息。

## 8. 次要能力：在线信源发现、来源核验与在线模型

- “在线能力验证”折叠区包含三个彼此独立的区块，不构成新的一级产品场景。
- 在线信源发现显示 `sourceDiscoveryMode`、单一提供方、当前查询和调用时间；搜索结果未进入 COLLECT 前显示“候选来源，尚未成为证据”。
- 权威来源核验显示 `authorityVerificationMode` 并明确写“固定白名单”，不能写“全网搜索”。两个动作不得混称。
- 在线候选生成显示 `synthesisMode` 与服务端配置状态；用户可选择`缓存模型输出`或`实时单端点`，但页面不接收、保存或回显 API Key。端点未由部署者预配置时，选择实时模式必须立即显示“未配置”并阻断运行。
- 每个来源一行显示成功/失败、HTTP 状态、字节和 SHA 摘要。
- 部分失败整体仍诚实显示，不把 3/4 写成 4/4；模型 Schema 或引用失败也保留原失败原因。
- 配置或网络失败即失败，不自动切换提供方、模型或静默使用缓存。
- 三种模式在运行顶部、交互报告、PPTX 与 JSON 中逐项一致；任一未运行项写 `NOT_RUN`，不能借另一项的成功显示“在线已验证”。

## 9. 视觉与可用性

- 视觉关键词：研究工作台、证据卡片、编辑报告；避免聊天气泡风格。
- 状态不能只靠颜色，必须有文字。
- 主要文字和控件满足桌面可读性；键盘可聚焦按钮、文件选择、页签和弹窗。
- `aria-live` 用于进度、上传和来源核验；错误使用 `role=alert`。
- 不出现横向溢出；长 URL/SHA 可换行。

## 10. 前端验收场景

### FE-E2E-01 黄金任务

从默认问题点击运行，观察 running，最终五步骤成功，看到 3–5 条候选、冲突和证据不足。

### FE-E2E-02 证据下钻

点击任意结论一次：有支撑项看到 Claim、Evidence/Datum、Assumption（如适用）、Source 和 locator；证据不足项看到完整 EvidenceGap。

### FE-E2E-03 人工决定

编辑一条可支持结论，保存后仍待确认；显式确认后显示 `HUMAN_CONFIRMED`、时间、确认文本与原模型文本。证据不足项可以编辑但无法确认。

### FE-E2E-04 来源更新

确认相关结论后载入内置 v2，旧决定保留但失效，相关文本/计算/PPTX 版本与哈希变化，无关结论不变。

### FE-E2E-05 恶意文件名上传

选择名为 `market-<img src=x onerror=alert(1)>.csv` 的真实 CSV，完成三方 SHA 复核，页面无 `img` 注入节点。

### FE-E2E-06 跨领域问题

输入光伏出口价格问题，计划范围包含光伏，不出现乘用车/充电候选结论，返回三条明确证据缺口。

### FE-E2E-07 候选生成来源

黄金任务页面明确显示缓存模型输出；显式在线模式显示实时模型；失配问题显示确定性阻断。三者不得混称。

### FE-E2E-08 信息架构理解

首次使用者无需工程师解释，能从三个一级章节完成运行任务、追问结论和更新成果；工具详情、上传和实时核验不会被误认为三个独立产品场景。

### FE-E2E-09 在线信源发现

在折叠区选择实时来源发现，页面显示单一提供方、查询和时间；成功结果持续标为候选来源。再模拟未配置/网络失败，状态为失败且不切换缓存。

### FE-E2E-10 固定白名单核验

独立运行固定白名单核验，顶部和导出只把 `authorityVerificationMode` 标为实时；逐项保留成功/失败，不能让它改变 `sourceDiscoveryMode`。

### FE-E2E-11 在线单端点模型

在服务端已安全预配置时选择实时单端点，PLAN/SYNTHESIZE 显示真实端点模式且模型候选通过引用/Schema 校验；缺配置、网络失败或非法引用均阻断，不自动改用缓存。
