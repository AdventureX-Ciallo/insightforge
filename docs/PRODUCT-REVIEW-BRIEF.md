# ChatGPT Pro 产品文档审查任务书

## 角色

你是外部高级产品与工程审查者。本轮只审查产品前期文档，禁止编写或修改代码，禁止声称运行了本地仓库、测试、构建、部署或用户调研。

## 背景

InsightForge 参加软件赛道，以一个作品同时满足：

- 商汤小浣熊：AI 不止完成一步；重点是 multi-step Agent、multi-tool use 和从需求到可编辑成果。
- 沙利文：PROOF OF INSIGHT；重点是研究问题、信源、证据、数据、类型、假设、判断、结论的可追溯连接，AI 自审、人负责最终判断、来源变化可追踪。

首轮原型在正式 PRD、前端需求和开发路径前已经出现。这是已确认的流程缺陷。当前开发已暂停，所有核心文档均为 DRAFT；历史代码和历史 PASS 不能倒推需求或证明 MVP 完成。

## 权威与边界

按此顺序审查：

1. 项目所有者最新明确指令、P0、禁止清单和权限边界。
2. 两份官方命题 PDF 原文；所有者可以收紧范围，但不能把官方未要求的能力宣传为官方要求。
3. `BRIEF-RESEARCH-EVIDENCE.md`。
4. `MVP-STRATEGY.md`、`PRD.md`、`DEVELOPMENT-SCOPE.md`。
5. 用户流程、前端需求、项目说明、决策、风险、验证、路线图和 P0 矩阵。

两份命题是本黑客松的首要产品调研证据，足以支持立项和产品方向。当前没有 InsightForge 真实用户研究，因此可以声称“符合命题/作品目标”，不能声称“市场需求或用户满意度已验证”。

硬边界：一个黄金案例、五状态、最多一次自动修复、三个成果；不做通用聊天、多 Agent、用户系统、多人协作、向量库、自动监控、第二行业案例、多模型路由、DOCX 输出、XLSX 输出或生产部署。P0-03/P0-12 明确允许读取与上传 XLSX，禁止的是 XLSX 成果生成。

## 审查问题

1. 两份命题是否被准确、完整且不夸大地转为产品要求？
2. 一句话定位与三个核心场景是否是最小且完整的产品，而非功能清单？
3. 三个场景是否覆盖十二条 P0；有无遗漏、重复或不必要功能？
4. 产品发现、PRD、范围、用户流程、前端需求、路线图、风险和验收是否存在术语、状态或责任冲突？
5. 是否清楚区分命题证据、用户/市场假设、历史实现证据和未来验收？
6. “模型提出、程序校验、人类决定”“缓存/实时”“上传保存/进入证据链”是否在产品和 UI 层面不可能被混淆？
7. 五分钟叙事是否自然，评委能否在不听技术补充的情况下理解两个高光？
8. 哪些内容可以进一步删除或降级，以降低 72 小时风险？

## 必须返回的交付物

请只返回产品文档审查，不返回代码：

1. `冻结结论`：`READY` 或 `NOT READY`，并给出不超过五句理由。
2. `阻断项`：按 P0/P1/P2 列出，包含文档、章节、冲突证据和最小修正建议。
3. `双命题追踪缺口`：命题原文要求→现有场景/需求→缺口。
4. `可删除项`：不伤害 P0 的进一步减法。
5. `不得声称`：列出任何当前文档可能诱发的夸大话术。
6. `冻结前检查表`：最多 12 项，可直接由项目负责人逐项确认。

如果没有读取到某个文件，请明确列出，不得假装已审查。不要继续做广泛市场研究，不要要求 API Key，不要提供 ZIP 或补丁，不要重新设计成另一种产品。
