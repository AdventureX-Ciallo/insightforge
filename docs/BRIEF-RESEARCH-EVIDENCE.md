## 1. 商汤小浣熊命题证据

### 官方命题事实

- 主题：`AI，不止完成一步`，软件赛道。
- 第 3 页描述：真实工作包含信息获取、分析判断、内容生成、文档处理和 PPT 制作等多个环节；AI 应通过搜索、数据分析、文档、表格、PPT、本地文件、Skill 等能力协同，把需求转成可用、可交付成果。
- 第 4 页把完整任务链拆成：`需求 → 理解与规划 → 工具/系统调用 → 执行与校验 → 成果交付`。
- 第 4 页强调产品不是聊天框，成果应可继续编辑、协作和复用。

### 项目所有者解释

命题重点是 `multi-tool use` 和 `multi-step agent`，不是把多个孤立工具摆在同一个页面，也不是模型在文本中声称调用了工具。

### 对 InsightForge 的硬推导

1. 用户从研究问题出发，只触发一条自然主流程。
2. 五个状态必须真实推进，前一步产物被下一步消费。
3. 同一次任务至少调用信源发现、PDF/本地文件、表格计算、PPTX 生成四类工具。
4. 执行失败必须传导到终态，不能播放预写成功动画。
5. 最终成果必须可继续阅读、编辑和机器复用。

## 2. 沙利文命题证据

### 官方命题事实

- 主题：`PROOF OF INSIGHT — 让行业判断经得起追问`，软件赛道。
- 第 1 页要求重新连接信源、证据、数据、判断与结论，形成可追溯、可验证、可持续更新的行业研究产品。
- 第 2 页给出链路：`研究问题 → 信源 → 证据 → 数据 → 事实/观点/估算 → 模型假设 → 判断 → 结论`。
- AI 的职责：发现信源、提取信息、识别冲突、形成候选判断、维护知识联系。
- 人的职责：检查证据、处理争议、确认边界、对最终结论负责。
- 目标体验：证据可见、判断可质疑、变化可追踪、成果可复用。

### 项目所有者解释

命题重点不仅是展示引用，还包括 Agent 对结构化输入进行自我审查并执行一次有边界的修正，使内容既可被人阅读，也可被 AI 识别、连接、调用和更新。

### 对 InsightForge 的硬推导

1. 研究对象必须使用机器可读 Schema 连接，不能只靠 UI 颜色和自然语言。
2. 有支撑的结论必须追到 Claim、Evidence/Datum、Source 和精确定位；证据不足项必须有明确 EvidenceGap，不能伪造来源。
3. 事实、来源观点、计算、估算、预测属于知识类型；AI 判断与人工确认属于责任/审阅状态，必须正交保存。
4. 冲突不得静默消解；证据不足必须 fail-closed。
5. AUDIT 必须读取当前结构化输入、发现问题并最多自动修复一次。
6. AI 只能生成候选，人工确认才产生 HumanDecision；编辑不等于确认。
7. 来源变化必须使相关对象失效并推动重算；不相关结论保持不变。

## 3. 两个命题的交集

两个命题不是两套功能，而是一条任务的两个维度：

| 维度 | 商汤回答 | 沙利文回答 | InsightForge 产品结果 |
|---|---|---|---|
| 任务是否完整 | 从需求推进到成果 | 研究内容可持续复用 | 五状态完整链与三种成果 |
| 工具是否真实 | 多工具/系统协同 | 来源、文件和数据进入证据链 | 四类工具产物被后续状态消费 |
| 判断是否可信 | 执行与校验 | 证据、冲突、假设和人工责任 | 模型提出、程序审查、人确认 |
| 成果是否可用 | 可编辑、可协作、可复用 | 可阅读、可连接、可更新 | 交互报告、可编辑 PPTX、证据 JSON |
| 变化如何处理 | 任务继续推进 | 变化可追踪 | v1→v2 失效、复核、重算和更新 |

## 4. 产品研究结论

### 立项结论

作品应定位为“证据原生的行业研究 Agent”，而不是通用聊天、单点报告生成器或通用知识图谱。

### 唯一主任务

把一个行业研究问题推进为可下钻、可质疑、可更新的研究成果。

### 三个核心场景

1. 一次任务运行五状态并交付三个真实成果。
2. 任一结论可下钻到底稿，冲突和证据不足不会被隐藏。
3. 来源更新使相关结论和人工确认失效，并刷新成果。

### 产品责任边界

`AI 发现和提出 → 程序验证和审查 → 人类决定 → 系统维护对象与成果版本的变化影响`

## 5. 追踪到十二条 P0

| 命题要求 | 对应 P0 |
|---|---|
| 干净环境、可体验、可交付 | P0-01、P0-10、P0-11 |
| multi-step 任务链 | P0-02 |
| multi-tool use | P0-03 |
| 结论追到底稿 | P0-04 |
| 事实/观点/计算/估算/预测/判断分型 | P0-05 |
| 冲突与证据不足 | P0-06 |
| Agent 自审与一次修正 | P0-07 |
| 人负责最终判断 | P0-08 |
| 变化可追踪与可更新 | P0-09 |
| 最低安全与来源指令惰性 | P0-12 |

十二条 P0 是命题证据的可执行化，不是额外堆叠的十二个独立产品模块。

## 6. 不从命题推出的内容

两份命题没有要求，且本期不开发：通用聊天、多 Agent 群体、用户系统、多人协作、向量数据库、自动全网监控、无限修复、多模型路由、DOCX/XLSX 输出、多 PPT 模板、第二行业案例和生产级平台化。
