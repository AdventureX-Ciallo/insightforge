## 3. 项目图片规格

只选能证明产品的四张图：

1. 问题输入与五状态真实运行。
2. 支持项的结论→Claim→Evidence/Datum→Source→Locator，或不足项的 EvidenceGap 下钻。
3. 内置 v1→v2 影响对象、旧人工决定失效记录与新 ArtifactVersion。
4. PowerPoint 中可编辑文本和来源编号。

禁止使用无法从产品复现的概念效果图冒充运行截图。截图中不得出现 API Key、用户名、绝对路径或真实用户数据。

## 4. 演示视频结构

按 `docs/PITCH-NARRATIVE.md`：

- 0:00–0:50 双命题问题、一句话方案并启动黄金任务。
- 0:50–1:35 完整任务链。
- 1:35–2:55 结论追问、计算/估算与人工判断。
- 2:55–3:50 来源更新失效。
- 3:50–4:25 三个成果。
- 4:25–5:00 三根技术支柱与收束。

录制前必须完成三次真实彩排。视频中明确显示离线快照，不声称实时网络或生产部署。

对外 README/提交说明只保留：

1. 项目背景与双命题证据。
2. 目标用户假设与核心 JTBD。
3. 三个场景与五状态任务链。

## 6. 提交前证据包

- 最终源码 commit、分支、dirty 状态。
- 安全源码 ZIP 大小与 SHA-256。
- 干净目录门禁日志。
- 三连跑时间与结果。
- PPTX 大小、SHA-256、Microsoft PowerPoint 打开/编辑证据。
- 实时信源发现/核验和单端点在线 LLM 的独立成功/失败证据；不以离线快照替代。
- 上传入口从浏览器到持久化复核的真实闭环证据；“已保存”与“进入证据链”分别验证。
- 项目图片与演示视频 SHA-256。
- 凭据扫描与依赖审计。
- ChatGPT Pro 对话链接与独立修正记录。
- 未验证风险清单。
